# 对标 sub2api 的功能补全计划

参照：`Wei-Shaw/sub2api`（43k star，Go + Vue3 的 AI API 网关平台）。
目标：把 cc-manage 从「账号池 + 公开看板 + 简易后台」补成一套**有可观测性、有 key 治理、
后台是正经控制台**的网关。**不改变**现有定位（单人自用 / 少量拼车），不引入 PG/Redis，
继续零运行时依赖（Node 内置模块）+ Docker。

## 一、差距清单（sub2api 有、我们没有的）

| # | 能力 | sub2api 对应 | cc-manage 现状 | 本次 |
|---|---|---|---|---|
| 1 | 请求日志：每次 `/v1/*` 一条明细（时间 / 客户端 key / 命中账号 / 模型 / 状态码 / 耗时 / 输入输出 token / 流式 / 来源 IP / 错误） | 使用记录 | 只有全局计数与错误事件 | ✅ |
| 2 | 用量统计：按 key / 按模型 / 按账号 / 按小时聚合，token 级（输入 / 输出），成本估算 | 精确计费 | 只有 `stats.total*` 与 `byAccount` 计数 | ✅ |
| 3 | API key 治理：备注 / 过期时间 / 启停 / 额度上限（5h / 日 / 周窗口）/ 最后使用时间 | API Key 分发 | 只有 name + 生成 + 删除 | ✅ |
| 4 | 每 key 限流：并发上限、每分钟请求上限 | 并发控制 / 速率限制 | 只有全局 `maxInflight` | ✅ |
| 5 | 后台 UI：左侧固定侧边栏 + 多页控制台（概览 / 账号 / 密钥 / 日志 / 用量 / 设置），统一数据表（筛选 + 分页 + 操作列） | Admin Dashboard | 单页四个卡片区块（drawer 导航） | ✅ |
| 6 | 系统设置页：可视化改轮询间隔 / 超时 / 上限 / 开关 | 系统设置 | 只能改 `config.json` 再重启 | ✅ |
| 7 | 审计日志：管理员写操作留痕（谁、何时、改了什么） | 审计日志 | 只有笼统的 events 缓冲 | ✅ |
| 8 | 分组（把账号分池、key 绑分组） | 分组 / Composite Groups | 无 | ⏸ 账号只有个位数，先不做 |
| 9 | 支付 / 订单 / 用户注册 / 优惠码 / 工单 / 插件 / 公告 | 同左 | 无 | ❌ 单机自用无关 |

## 二、批次拆分（一轮 = 一个可验收交付物）

- **B50 请求日志与用量数据层**（后端）：`src/usage.mjs`（每请求一条 + 落盘 + 查询 + 聚合）、
  `/v1/*` 挂钩、`GET /api/admin/usage`、`GET /api/admin/logs`。
- **B51 客户端 key 治理**（后端）：`keys.json` 字段扩展（remark / expiresAt / enabled / quota 窗口 /
  maxConcurrency / rpm）+ 执行与 429 语义 + 管理 API。
- **B52 后台控制台骨架 + 账号池页 + 密钥页**（前端）：侧边栏布局、页面拆分、把 B51 字段接上。
- **B53 请求日志页 + 用量统计页**（前端）：数据表（筛选/分页/搜索）+ ECharts 图表。
- **B54 概览仪表盘 + 系统设置页 + 审计日志页**（前端 + 少量后端）。

## 三、每批验收（不变）

1. `node --test --test-concurrency=8 test/*.test.mjs` 全绿，基线数字写进 brief；
2. mutation check：定向变异后对应断言必须变红；
3. 前端批次：`bash scripts/panel-build.sh` + 真机几何/截图复核；
4. 部署、push、CI 逐 job 判绿 —— 全部留到批次结束后一次性做。

## 四、风险

- 后台现有断言（`ui-structure` / `b25-admin-progress-a11y` / `frontend-b19` / `detail-modal`）密集，
  拆页会作废若干结构断言 → 按「保留钩子优先、否则等强度重写」处理，且**一条旧断言换一条新断言**。
- 请求日志是新增写盘路径，必须限流 + 轮转（保留 N 天 / 单文件上限），不能把 2GB 小盘写满。
- key 配额执行会让「本地自用 key」有被限死的可能 → 默认不限额（字段缺省 = 不限）。
